## 一、IntentAgent 三层架构总览

创新点 #2 是一个**三阶段逐级增量**的检索智能体系统：

```
阶段 A · 静态路由（M-R-D-E）
  └→ 阶段 B · 动态编排（LangGraph Agent + 反思回路）
       └→ 阶段 C · 经验记忆（Experiential Memory，类 Claude Code 磁盘记忆）
```

三阶段都对外实现同一个 `BaseRetriever.retrieve(query, top_k) -> RetrievalResult` 契约，通过一行 yaml 切换、可独立消融。消融实验中，从 Full（A+B+C）逐级移除各组件的 EM 下降幅度，直接量化了每层的贡献。

---

## 二、阶段 A：静态路由（M-R-D-E）—— 意图驱动策略选择

### 2.1 核心机制

传统 RAG 方法（Vanilla RAG、RAPTOR、LightRAG）对所有查询使用**同一种检索策略**——向量相似度检索。但不同类型的查询需要截然不同的检索方式：

| 查询意图                | 最优策略                      | 典型问题                                               | 单一向量检索的问题             |
| ----------------------- | ----------------------------- | ------------------------------------------------------ | ------------------------------ |
| `factual`（事实型）     | `direct`（直接检索）          | "When was Einstein born?"                              | 尚可处理                       |
| `analytical`（分析型）  | `iterative`（迭代分解）       | "Why did the Roman Empire fall?"                       | 需要分解子问题，向量检索做不到 |
| `comparative`（对比型） | `parallel`（并行双路）        | "Compare iPhone 15 and Galaxy S24"                     | 只能命中一个实体，对比失败     |
| `multi_hop`（多跳型）   | `multi_hop`（图扩展）         | "What is the birth city of the director of Inception?" | 证据链断裂，无法桥接           |
| `exploratory`（探索型） | `expansion`（扩展图遍历）     | "Tell me about quantum computing"                      | 覆盖范围不足                   |
| `follow_up`（追问型）   | `context_aware`（上下文感知） | "What about her husband?"                              | 无会话记忆，不理解指代         |

IntentAgent 通过 **LLM + 规则双路意图分类器**（`LLMIntentClassifier`）将查询分类为 6 类意图，再由 `IntentReasoner` 通过**纯查表**（`_INTENT_TO_STRATEGY`）映射到对应策略，零额外 LLM 开销。

### 2.2 为什么这能超过 baselines

**消融证据：** w/o Intent（移除意图分类，全部用 direct 策略）→ EM 下降 ~14%，是所有消融变体中降幅最大的。

**本质原因：** 其他方法都存在"一种策略打天下"的结构性缺陷：

- **Vanilla RAG / RAPTOR / LightRAG：** 全部用向量检索 → 多跳查询（如 2Wiki 的桥接题）必然失败，因为需要跨文档的证据链接，而非单个文档内的相似语义匹配
- **HippoRAG / HippoRAG2：** 全部用个性化 PageRank（PPR）图扩散 → 对事实型查询过度检索（引入噪声实体），对对比型查询缺少并行检索两实体的能力
- **GraphRAG：** 全部用社区摘要 → 对精确的事实查询引入了大量无关社区信息，丢失实体级细粒度
- **TOG：** 全部用 LLM beam search 图遍历 → 对简单事实型查询过度消耗 token，且有 beam 漂移噪声

我们的 6 策略路由本质上是**承认查询的异质性**——不同类型的查询应该用不同的方法解决。这是所有 baseline 在架构层面没有做的事。

## 三、阶段 B：动态编排（LangGraph Agent）—— 从"选一种策略"到"组合多种工具"

### 3.1 核心机制

阶段 A 的静态路由有一个根本局限：**一个查询只能命中 6 类意图之一，执行单一策略**。但真实的复杂查询往往是跨意图的——比如"比较 A 和 B 为什么不同"，既需要 `comparative`（比较），也需要 `analytical`（分析原因）。

阶段 B 将 Decision 阶段从**静态查表**升级为 **LangGraph 状态图 + LLM 自主选择/组合多工具**：

```
5 个原子检索工具:
├── vector_search       — 向量相似度检索
├── graph_neighbors     — 图邻居扩展
├── multi_hop_retrieve  — 多跳链式检索
├── parallel_retrieve   — 并行多路检索
└── assess_evidence     — 证据质量评估
```

LLM Agent 在状态图中自主决定调用哪些工具、以什么顺序调用。5 节点状态图（memory → reasoning → decision → tools → reflect）构成决策闭环。

### 3.2 反思回路：检索质量自检

这是阶段 B 最关键的创新。在阶段 A 中，反思（Reflection）只做**观测写回**——把 `reflection_quality` 写入 metadata，但不触发任何行为改变。

阶段 B 的 `reflect_node` + `route_after_reflect` conditional edge 真正实现了质量门控的检索重试：

```
reflect_node 评估证据质量
  ├── quality ≥ threshold (0.6) → END（证据充分）
  ├── iteration_count ≥ MAX (2)   → END（达迭代上限）
  └── 质量不足且未触顶 → 回到 decision_node，换工具/加跳数重试
```

**消融证据：**

- w/o Dynamic（静态路由，无反思回路）→ EM 下降 ~7%
- w/o Reflect（有动态编排但无反思）→ EM 下降 ~6%

检索质量分析（HotpotQA）进一步证实：

| 变体                 | 证据覆盖率        | 平均相关性 |
| -------------------- | ----------------- | ---------- |
| 静态路由（阶段 A）   | 0.554             | 3.61       |
| + 动态编排（阶段 B） | 0.700 (+14.6%)    | 4.01       |
| + 经验记忆（阶段 C） | **0.738** (+3.8%) | **4.26**   |

### 3.3 为什么这能超过 baselines

**核心差异——检索过程的自主决策 vs 固定流程：**

| Baseline               | 检索决策模式                    | 局限                                                        |
| ---------------------- | ------------------------------- | ----------------------------------------------------------- |
| Vanilla RAG / LightRAG | 固定：向量 top-k                | 无决策空间                                                  |
| RAPTOR                 | 固定：树遍历                    | 只能上下移动，无法横向切换检索模态                          |
| TOG                    | LLM beam search                 | 有决策但"暴力探索"，O(beam_width × hops) 成本，且 beam 漂移 |
| G-Retriever            | 固定：GNN embedding             | 跳数、策略均不可调                                          |
| GraphRAG               | 固定：社区选择                  | 社区预计算，运行时不可调整粒度                              |
| HippoRAG/HippoRAG2     | 固定：PPR 扩散                  | 扩散模式单一，无工具组合                                    |
| **IntentAgent**        | **LLM 自主工具选择 + 反思回路** | 按需组合、质量不足时重试                                    |

**关键优势：**

1. **跨意图查询的组合能力：** 静态路由对混合意图被迫二选一，LangGraph Agent 可以"先 parallel_retrieve 比较两个实体，再 multi_hop_retrieve 追究原因"，自由组合工具。

2. **反思回路是检索的"安全网"：** 所有 baseline 的检索结果都是一次性的——质量差只能认栽。我们的反思回路在检索质量不足时**主动换工具重试**（参见 Case Study 案例 3：第 2 跳图扩展失败 quality=0.31 → 切换为文本检索 → 完成三跳推理）。

3. **比 TOG 更高效：** TOG 的 LLM beam search 每跳需要 LLM 对每个候选打分（O(beam_width × hops) 次 LLM 调用）。我们通过 LangGraph `bind_tools` + ReAct 文本协议，LLM 只在 decision_node 被调用，最多 `max_iterations=2` 轮，成本可控。

## 四、阶段 C：经验记忆（Experiential Memory）—— 跨查询学习能力

### 4.1 核心机制

阶段 B 的 LangGraph Agent 每次查询都是"从零思考"——即便前一个同类问题已经摸索出了成功路径，下一个同类问题到来时 LLM 仍要重新试错。

阶段 C 引入**类 Claude Code 的磁盘记忆**，构成"入口召回 → 核心检索 → 出口沉淀"三段式闭环：

```
入口（读）：意图分类 → 按 intent 从磁盘经验库 recall top-3 → 拼成 SystemMessage 注入
         ↓
核心（零改动）：2b 的 Decision ⇄ Tools ⇄ Reflect 回路，LLM 多看一段经验提示
         ↓
出口（写）：build_experience_entry → 按 quality_threshold 分流 →
           ├── quality ≥ τ → success: 保存工具序列 + QA pair（可复用）
           └── quality < τ → lesson: 保存规避教训（下次避免）
         → remember() 去重合并落盘
```

**磁盘布局（按意图分桶，JSONL）：**

```
.chimera_memory/experience/
├── factual.jsonl
├── analytical.jsonl
├── comparative.jsonl
├── multi_hop.jsonl
├── exploratory.jsonl
└── follow_up.jsonl
```

**召回结果的注入形式：**

```
历史上同类问题的检索经验（仅供参考，可自主决策）：
  ✅ 成功路径(quality 0.82): graph_neighbors → multi_hop_retrieve
  ✅ 成功路径(quality 0.75): vector_search → graph_neighbors
  ⚠️ 规避教训: intent=multi_hop 时，工具序列 vector_search 质量仅 0.42；建议补充 graph_neighbors
请优先参考成功路径，避免已知的低效做法。
```

关键设计：经验是**强先验，不是硬约束**——LLM 仍自主决策，不会因为一条过时经验而被锁死。

### 4.2 飞轮效应

**消融证据**——经验记忆增长曲线（HotpotQA，Qwen3-32B）：

| 查询窗口      | EM    | 累计提升  |
| ------------- | ----- | --------- |
| 1–50 (冷启动) | 0.424 | —         |
| 51–100        | 0.455 | +3.1%     |
| 201–300       | 0.474 | +5.0%     |
| 401–500       | 0.495 | **+7.1%** |

冷启动阶段经验库为空，无经验可用（EM=0.424）。处理 50 个查询后同类问题的经验开始积累（+3.1%）。300 查询后增速放缓趋于饱和（+7.1%）。F1 呈现相同趋势，从 0.571 提升至 0.647（+7.6%）。

### 4.3 为什么这能超过 baselines

**这是所有 baseline 都不具备的能力——跨查询、跨 session 的学习：**

| Baseline                                            | 学习能力                           |
| --------------------------------------------------- | ---------------------------------- |
| Vanilla RAG / RAPTOR / TOG / G-Retriever / LightRAG | 无状态，每次查询完全独立           |
| GraphRAG                                            | 社区摘要在构建时固定，无运行时学习 |
| HippoRAG / HippoRAG2                                | 无跨会话记忆，PPR 扩散模式不变     |
| **IntentAgent**                                     | **磁盘经验记忆，越用越聪明**       |

具体来说有两个层面：

1. **成功复用（提高上限）：** 同类问题直接提示历史成功路径，LLM 更快选对工具，减少试错轮数。这在批量评测场景下尤为明显——前 500 题中后 200 题的平均质量显著高于前 100 题。

2. **失败规避（提高下限）：** 历史上低质量的工具序列被标记为 `lesson`，召回到时直接提示"上次这样做不行"，防止 LLM 重蹈覆辙。这对 MuSiQue 这类极难数据集的提升尤为关键——即使不能完全做对，也能避免最差的检索策略。

## 五、Dual-Path 双路径兜底

### 5.1 核心机制

LLM 意图分类在边缘 case 上可能出错。Dual-Path 同时运行两条路径：

- **LLM 路径：** `LLMIntentClassifier` → 语义意图（6-way 分类）
- **规则路径：** 7 条关键词正则（从特殊到一般）→ 规则意图

两路结果不一致时，取更保守的规则路径，确保策略选择不因 LLM 的偶发错误而失效。

### 5.2 为什么有效

**消融证据：** w/o Dual-Path → EM 下降 ~3%，虽然降幅不大但在边缘 case 上至关重要。

参见 Case Study 案例 5：LLM 将 "list the Nobel Prize winners" 误判为 `aggregation`，规则路径通过关键词 `list` 正确识别为集合检索。Dual-Path 在两路不一致时取规则路径，避免了策略错配导致的不完整回答。

**与 baselines 的对比：**

- HippoRAG 的节点重要性评分完全依赖 LLM → 分类错误直接影响 PPR 扩散质量
- GraphRAG 的社区选择依赖 embedding 相似度 → 无逻辑兜底
- Vanilla RAG 无分类步骤 → 不需要兜底但也失去了策略选择能力

## 七、数据集维度的优势分析

### 7.1 2WikiMultiHopQA（优势最大）

2Wiki 需要**跨两篇 Wikipedia 文章进行桥接推理**，查询类型以 `multi_hop` 为主。

- IntentAgent 的 `multi_hop` 意图 → `MultiHopStrategy` 精确执行两跳图扩展
- HippoRAG2 的 PPR 扩散虽能关联实体，但会引入不相关文章的噪声实体
- Vanilla RAG / RAPTOR 的单文本检索在桥接查询上根本性失败（证据链断裂）
- **意图路由在此数据集价值最大：** 桥接查询占比高，意图分类准确 → 策略选择准确

### 7.2 HotpotQA（优势最稳定）

HotpotQA 混合了桥接、对比、事实型等**多种查询类型**，查询多样性最高。

- **意图路由的价值在此数据集中被最大化：** 不同查询类型需要不同策略，且动态编排可以组合多种工具处理跨意图查询
- GraphRAG 的社区摘要在桥接查询还行，但在对比和事实型查询中引入过多无关信息
- **消融实验的各组件均在此数据集上表现出显著差距**（全组件 EM 差距最大）

### 7.3 MuSiQue-Ans / MuSiQue-Full（与 HippoRAG2 最接近）

MuSiQue 是**最难的推理链数据集**（2-4 跳组合）。

- HippoRAG2 的多跳路径聚合在 3-4 跳链式推理中有架构优势
- IntentAgent 的反思回路在 2-3 跳场景效用显著，但 `max_iterations=2` 限制了 4 跳场景的重试深度
- 经验记忆在此数据集的帮助在于：同类型多跳查询可以复用成功路径，减少试错
- **改进方向：** 增加 `max_iterations` 或引入更灵活的反思策略，缩小与 HippoRAG2 在极端多跳场景的差距

## 八、总结

IntentAgent 超越 baselines 的核心原因可归结为**四个 baselines 不具备或只部分具备的能力**：

```
性能优势 ≈ 意图路由 (~14%) + 动态编排 (~7%) + 反思回路 (~6%) + 经验记忆 (~4%) + 双路径兜底 (~3%)
```

| 能力               | 对应阶段 | EM 贡献   | Baselines 的状况                               |
| ------------------ | -------- | --------- | ---------------------------------------------- |
| 意图感知的策略选择 | 阶段 A   | ~14%      | 所有 baseline 均无——一律用一种方法处理所有查询 |
| LLM 自主工具组合   | 阶段 B   | ~7%       | TOG 有部分（beam search），但成本高且有噪声    |
| 检索质量自检与重试 | 阶段 B   | ~6%       | 所有 baseline 均无——检索结果差只能认栽         |
| 跨查询经验积累     | 阶段 C   | ~4%+ 飞轮 | 所有 baseline 均无——每次查询从零开始           |
| 分类错误容错       | 阶段 A   | ~3%       | 无 baseline 有冗余兜底机制                     |

**核心洞察：** 这不是"一个更强的检索算法"打败了其他检索算法，而是一个**多阶段智能编排系统**打败了**单一检索策略的方法**。各 baseline 各自在一个维度上做得不错（HippoRAG2 在图扩散、GraphRAG 在摘要聚合、RAPTOR 在层次树），但都没有解决"不同查询应该用不同方法"这个根本问题。IntentAgent 的三阶段架构（A→B→C）正是围绕这个核心洞察设计的——先分类（A），再动态组合（B），最后积累经验让下次更快（C）。
