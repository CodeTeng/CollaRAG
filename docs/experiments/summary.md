# 大纲

---

## 一、引言

- 问题背景：RAG 系统普遍采用统一检索策略，忽视查询意图的多样性
- 核心命题：查询意图应当成为检索策略选择的一等公民
- 三类查询示例：事实型、多跳推理型、对比型 — 需要不同的检索路径
- 三阶段渐进演化设计哲学：在可控性与自适应性之间取得平衡
  - 阶段一：静态意图路由（确定性映射表）
  - 阶段二：动态工具编排（LLM 驱动的有向状态图）
  - 阶段三：经验记忆增强（三段式闭环的跨会话自我进化）
- 实验概览：HotpotQA / 2WikiMultiHopQA / MuSiQue，三个骨干模型（Gemma4-12B, Qwen3-8B, Qwen3-32B）
- 贡献总结（四点）

## 二、相关工作

- 查询改写路线：HyDE、Query2Doc

- 图增强检索：GraphRAG、LightRAG、HippoRAG、TOG、G-Retriever、RAPTOR

### 2.2 意图识别与查询理解

- Web 搜索意图分类：Broder（导航/信息/事务），Jansen 等人的实证分析
- 对话系统中的 NLU 意图识别
- LLM 零样本/少样本分类能力
- 本文区别：六类意图分类是面向检索策略差异化设计的，直接对应检索策略

### 2.3 基于智能体的检索与经验学习

- 智能体驱动检索：ReAct、Tree of Thoughts、Toolformer
- 经验学习：Reflexion、Voyager、MemoRAG
- 本文推进：
  1. 意图分类作为先验信息注入
  2. 显式反思回路实现质量门控
  3. 意图分桶经验存储（成功路径 + 失败教训二分类）

## 三、方法

### 3.1 问题形式化

- 定义：知识库 K、知识图谱 G、查询 q、检索证据 R(q)
- 核心主张：最优检索函数应依赖查询意图类型
- 意图分类函数 φ: q → l ∈ L（六类意图标签）
- 策略族 S = {s*l}，目标函数：R\*(q) = s*{φ(q)}(q, K, G)

### 3.2 系统总览

- M-R-D-E 四阶段处理流水线：
  - **Memory**：会话历史读取 + 经验记忆召回
  - **Reasoning**：LLM+规则双路意图分类，输出推理计划
  - **Decision**：推理计划 → 检索策略实例（静态映射 / 动态编排）
  - **Execution**：执行策略 → 证据收集 → 重排序 → 反思评估
- 注册表驱动的可插拔架构：三个阶段间切换仅需修改一行配置

### 3.3 阶段一：静态意图路由

#### 3.3.1 LLM+规则双路分类器

- 主路径：LLM 结构化提示词 → JSON 分类结果 → 解析验证（JSON→围栏→贪心，三级降级）
- 规则路径：7 级优先级有序正则级联（比较类→因果/影响→原因类→跟进类→探索类→事实类→默认兜底）
- 双路意义：LLM 捕捉语义微妙意图，规则保证鲁棒性和可用性

#### 3.3.2 意图-策略确定性映射

- 六类意图 × 六种策略的确定性映射表：
  | factual → 直接检索 | analytical → 迭代检索 | comparative → 并行检索 |
  | multi_hop → 多跳检索 | exploratory → 扩展检索 | follow_up → 上下文感知检索 |
- 策略实现细节：各自委托给基础检索组件

#### 3.3.3 端到端流程

- 六步流程：会话历史读取 → 分类 → 策略查找（带缓存）→ 异步执行 → 可选重排/反思 → 元数据写入

### 3.4 阶段二：动态工具编排

#### 3.4.1 动机

- 静态路由三大局限：
  1. 跨意图盲区：无法处理混合意图查询
  2. 无运行时反馈：策略选定后固定执行
  3. 组合爆炸：手工编写混合策略不可行

#### 3.4.2 工具封装

- 五个结构化工具（薄包装、零新检索逻辑）：
  - 向量检索 / 图邻居扩展 / 多跳检索 / 并行检索 / 证据评估
- 共享工具上下文：片段 ID 去重、保留最高分数
- Token 控制：返回紧凑结构化字典而非完整文本

#### 3.4.3 有向状态图驱动的智能体工作流

- 五节点有环有向状态图：
  `START → memory → reasoning → decision ⇄ tools → reflect → END`
- 节点功能：memory（会话历史）、reasoning（意图提示）、decision（LLM 工具选择）、tools（执行）、reflect（质量评估）
- 两条条件边：decision→tools/reflect；reflect→decision（质量不达标时重新规划）/END
- 质量门控反思回路：quality ≥ τ 或轮次 ≥ max 时终止

#### 3.4.4 推理-行动协议适配

- 协议适配器：将通用 LLM 接口包装为聊天模型
- 不依赖特定 LLM 提供商的函数调用能力

### 3.5 阶段三：经验记忆增强

#### 3.5.1 动机

- 阶段二局限：每次查询从零开始，历史经验在会话结束后丢失

#### 3.5.2 经验条目数据模型

- 字段：意图标签、查询文本、工具序列、迭代次数、质量分数、结果分类、规避原因、答案、证据 ID、热度计数、时间戳
- 二分类：成功路径（quality ≥ τ，保留全部）/ 失败教训（quality < τ，仅保留工具序列+规避说明）

#### 3.5.3 三段式闭环

- **入口读（Recall）**：意图分桶召回 top-N 经验，按 (quality, hit_count) 降序排列
- **核心用（Inject）**：经验渲染为结构化系统消息注入状态图（提示而非约束）
- **出口写（Persist）**：蒸馏工具序列+质量分数，写入持久化存储

#### 3.5.4 持久化存储设计

- JSONL 格式（每个意图一个文件），原子写入 + 崩溃恢复
- 去重机制：(工具序列, 结果分类) 相同时合并更新
- 淘汰机制：容量上限 200，按 (hit_count, created_at) 淘汰最冷最旧条目
- 召回复杂度：按意图分桶，仅读取小文件

## 五、分析与讨论

### 5.1 意图感知的必要性

- "w/o Intent" 消融证据：移除意图分类后多跳和对比型查询性能大幅下降
- 验证核心命题：不同意图确实需要差异化检索策略

### 5.2 从静态到动态的价值

- "w/o Dynamic" 消融证据：跨意图查询和运行时自适应场景的边际价值
- "w/o Reflect" 消融证据：反思回路的不可替代贡献

### 5.3 经验记忆的飞轮效应

- "w/o Memory" 消融量化边际贡献
- 三重效应：冷启动→热启动收敛 / 正反馈循环（热度→优先级） / 避免重复犯错

### 5.4 局限性

- 意图分类覆盖性不全面（时序推理、数值计算等）
- LLM 意图分类的额外开销（~200 token）
- 经验记忆的时效性问题（缺乏基于知识库版本的经验过期机制）

---

## 六、结论

- 核心贡献回顾：意图感知检索范式 × 三阶段渐进演化
- 实验结果总结
- 未来工作三个方向：
  1. 层次化意图分类（细粒度子类型）
  2. 经验记忆的向量化检索（语义级别相似经验召回）
  3. 跨模态扩展（图文混合知识库）
