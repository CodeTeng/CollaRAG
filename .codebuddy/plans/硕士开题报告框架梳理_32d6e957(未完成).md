## 用户需求

为"李腾"同学的硕士研究生开题报告生成一份**完整、工程实施风格**的开题框架 Markdown 文档，基于仓库中已有的 5 份技术材料（`my/` 目录）与学校模板（`.doc`），整合并优化为一份可直接用于导师技术评审的开题报告。

## 核心要求

1. **题目优化**：将原题「意图感知的 RAG 技术研究」优化为更聚焦两大创新点的表述（建议：**面向意图感知的图增强检索生成关键技术研究**），并在报告中给出优化理由。
2. **逻辑主线打通**：显式呈现「**高质量知识构建 (DEKER) → 意图驱动检索推理 (MRDE) → 构建-检索闭环**」的研究主线，弥合现有两份材料中两创新点关联性不强的问题。
3. **创新点2 架构**：统一采用 **方案C：MRDE 四模块为核心 + Reflection / Reranking / Parallel Retrieval 作为可插拔子模块**，不复述 8 智能体完整方案。
4. **文档形式**：完整 Markdown 开题报告（约 20-30 页规模），包含 10 个标准章节：

- 论文题目与方向、研究背景与意义、国内外研究现状、研究内容与创新点、关键技术与技术路线、实验方案、研究计划与进度安排、预期成果、核心代码模块规划、参考文献

5. **风格**：工程实施风格，含 Mermaid 技术路线图、Markdown 甘特图表、算法公式、代码目录树；面向导师技术评审；中文撰写，术语保留英文。
6. **输出位置**：在 `/Users/teng/Projects/my/agent-graph-rag/my/` 目录下新建 `研究生开题报告框架.md`，不修改已有 5 份材料。

## 内容边界

- 基于 Youtu-GraphRAG 基础框架，研究周期 2026 年 3 月 - 2027 年 3 月（12 个月）。
- 主数据集 HotpotQA，补充 2WikiMultihopQA / MusiqueQA；基线含 Naive RAG / LangChain / Microsoft GraphRAG / Youtu-GraphRAG / RQ-RAG。
- 量化目标：EM +10-15%、F1 +12-18%、Retrieval Precision +15-20%、KG Quality +20-30%、Intent Accuracy >85%、Redundancy Rate -50%+。
- 目标产出：1 篇硕士学位论文 + 1-2 篇会议/期刊论文（EMNLP / ACL / COLING）。

## 技术栈

- **文档载体**：Markdown（GFM），Mermaid 代码块绘制架构图/流程图/甘特图，Markdown 表格呈现进度与指标对比。
- **内容来源**：整合 `my/` 目录下 5 份现有材料（快速参考卡 / 完整实施方案 / 知识构建双重增强 / 多智能体架构设计 / 多智能体集成方案）。

## 总体方法

采用"**主线先行 + 模块化拼装 + 工程视角贯穿**"的撰写策略：

1. 先在第 4 章显式绘制"**DEKER → MRDE 闭环主线图**"，统领全文；
2. 第 5 章对每个技术模块给出「问题定义 → 核心公式/伪代码 → 集成点（仓库文件）」三段式描述；
3. 第 7 章用 Mermaid Gantt + Markdown 表格双形态呈现进度，每月列出可验证交付物；
4. 第 9 章以目录树 + 文件职责表方式给出代码模块规划，与仓库现有 `models/constructor/`、`models/retriever/` 对齐。

## 关键设计决策

1. **题目优化理由**：原题"意图感知的 RAG 技术研究"未体现"图增强"和"知识构建优化"维度，创新点 1（KG 构建）被掩盖。优化题目"**面向意图感知的图增强检索生成关键技术研究**"覆盖图、意图、关键技术三层，与两创新点精准对应。
2. **双创新点主线统一**：以"**知识质量 × 检索智能**"为二维主线——创新点 1 解决"知识图谱输入端质量"（Garbage-in-Garbage-out），创新点 2 解决"查询理解与推理端智能"；二者通过"意图驱动的多层级检索接口"耦合（MRDE 的检索策略直接消费 DEKER 产出的分层 KG：节点/关系/社区/块）。
3. **方案 C 的架构落地**：MRDE 主循环固定四阶段，但 Decision/Execution 阶段通过策略注册表动态挂载可插拔子模块——ReflectionHook（执行后质量评估+反馈）、RerankingHook（检索后 cross-encoder 重排）、ParallelRetrievalPool（comparative/multi_hop 意图下启用子智能体池）。这样既保持单智能体的工程简洁性，又保留多智能体方案的可扩展性。
4. **工程实施风格的体现**：

- 每个模块提供"**输入 → 算法 → 输出 → 仓库集成点（精确到文件与方法名）**"四元组描述；
- 技术路线图采用 Mermaid flowchart + sequenceDiagram 双视图；
- 进度安排采用 Mermaid Gantt 图 + Markdown 表格双形态，含风险矩阵。
